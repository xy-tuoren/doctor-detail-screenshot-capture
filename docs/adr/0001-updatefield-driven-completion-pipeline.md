# 以莲藕 updateField 为驱动的单向补全管线

整条流程的"该做什么"完全由莲藕系统查询接口返回的 `updateField`（缺失字段）决定：缺哪些字段就补哪些、缺哪类图就采集谁，工作名单由查询结果自动派生，不再手工维护 `config.json` 的 `namesMain/namesMulti`。

数据是**单向**流动的——莲藕是唯一的真相源与写回目标；机构端 UI 导出、卫健委/机构端截图都是用来补全莲藕的输入，彼此不互相写回。

之所以这样定，是因为"缺什么补什么"避免了无意义的全量重采集，也让缺失名单（莲藕有、机构端导出查不到）的人工处理边界清晰。代价是强依赖 `updateField` 的准确性；若该字段不可靠，整条管线的取舍都要重估。
